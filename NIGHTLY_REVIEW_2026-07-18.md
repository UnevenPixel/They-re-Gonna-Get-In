## 3. Potential problems

### Worth a direct look

1. **`scripts/CastleScripts/CastleScripts.gml`, `CastleDefendWaypoints` (~lines 126-131) — misleading variable name, not a functional bug.** `_onLeftSide = (_distLeft < _distRight)` is true when the castle's front edge is on `bbox_left`, i.e. when the castle sits on the *right* side of the room. The offset math downstream is correct either way, but the name says the opposite of the condition. `StationScripts.gml`'s `StationDeploySpawnPoint` computes the same condition and names it correctly (`_isFrontRight`). Worth a rename (e.g. `_frontIsLeftEdge`).

2. **`scripts/AnalyticsScripts/AnalyticsScripts.gml:39-64`, `AnalyticsInit()` — `ds_map` leak on match restart.** Creates 8 fresh `ds_map_create()` handles per team, every call, never destroys the previous set. `PauseMenuScripts.gml`'s `DoRestart()` (line 175-178) calls `room_restart()`, which re-runs `oMatchControl`'s Create event and re-invokes `AnalyticsInit()` — so every "Restart" from the pause menu orphans the prior match's 8 `ds_map`s. Should destroy the existing maps (if `global.analytics` already exists) before recreating them.

3. **`scripts/SettingsOverlayScripts/SettingsOverlayScripts.gml:198-213`, `ApplyGameSettings()` — Borderless Windowed toggle doesn't restore window size on disable.** Turning it ON forces `window_set_position(0,0)` + full-display resize (lines 210-212). Turning it back OFF only calls `window_set_showborder(true)` (line 209) — size/position from before enabling borderless are never restored. Net effect: unchecking Borderless leaves the window at full-display size but with a title bar/border added on top, likely overflowing the visible screen. Still un-pushed to GitHub (see §0) — worth fixing before this feature ships.

4. **`scripts/UnitCombatHelpers/UnitCombatHelpers.gml:277`, `UnitTryDealDamage` — Bomb Goblin self-destruct uses a hardcoded object check instead of the tag system.** Gated on `_unit.object_index == oBombGoblinUnit` instead of the tag-based dispatch used everywhere else. Bomb Goblin's own definition already has a `"suicide"` tag (`UnitDefinitions.gml:445`) but it's unused here. A second suicide-type unit would need its own hardcoded branch instead of being picked up automatically.

### New this pass

5. **`scripts/AnalyticsScripts/AnalyticsScripts.gml:116-146`, `AnalyticsRecordKill`/`AnalyticsRecordDeath` — stale doc comments, not a functional bug.** Both doc blocks claim these are "NOT WIRED ANYWHERE YET" because "there's no 'unit died' event" and "`UnitTryDealDamage`'s actual damage calculation is still an unimplemented TODO." Neither is true anymore: `ApplyDamage` (`UnitCombatHelpers.gml:131,135`) calls both functions on every kill/death, and the damage calc itself is fully implemented (only knockback remains a TODO). Misleading for anyone reading this file cold — worth a one-line doc update to reflect that kill/death tracking is live.
