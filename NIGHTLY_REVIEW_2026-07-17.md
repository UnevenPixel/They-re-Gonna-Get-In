## 3. Potential problems

### Worth a direct look

1. **`scripts/CastleScripts/CastleScripts.gml`, `CastleDefendWaypoints` (~lines 126-131) — misleading variable name, not a functional bug.** `_onLeftSide = (_distLeft < _distRight)` is actually true when the castle's front edge is on `bbox_left`, i.e. when the castle sits on the *right* side of the room. The offset math downstream is correct either way (verified by walking both branches), but the name says the opposite of the condition. `StationScripts.gml`'s `StationDeploySpawnPoint` computes the same front-edge condition and names it correctly (`_isFrontRight = (_distRight < _distLeft)`). Worth a rename (e.g. `_frontIsLeftEdge`) so a future edit doesn't misread the branch.

2. **`scripts/AnalyticsScripts/AnalyticsScripts.gml:39`, `AnalyticsInit()` — ds_map leak on match restart.** Creates 8 fresh `ds_map_create()` handles every call and never destroys the previous set. `PauseMenuScripts.gml`'s `DoRestart()` calls `room_restart()`, which re-runs `oMatchControl`'s Create event and re-invokes `AnalyticsInit()` — so every "Restart" from the pause menu orphans the prior match's 8 ds_maps. No `ds_map_destroy` call anywhere tied to `global.analytics`. Should destroy the existing maps (if `global.analytics` already exists) before recreating them.

3. **`scripts/SettingsOverlayScripts/SettingsOverlayScripts.gml:198-215`, `ApplyGameSettings()` — Borderless Windowed toggle doesn't restore window size on disable.** Turning it ON forces `window_set_position(0,0)` + `window_set_size(display_get_width(), display_get_height())`. Turning it back OFF only calls `window_set_showborder(true)` — size/position from before enabling borderless are never restored. Net effect: unchecking Borderless leaves the window at full-display size but now with a title bar/border added on top, likely overflowing the visible screen. This is new/recent code (part of the still-uncommitted Settings overlay work), worth fixing before that feature ships.

4. **`scripts/UnitCombatHelpers/UnitCombatHelpers.gml`, `UnitTryDealDamage` (~line 277) — Bomb Goblin self-destruct uses a hardcoded object check instead of the tag system.** Gated on `_unit.object_index == oBombGoblinUnit` instead of the tag-based dispatch used everywhere else (e.g. `UnitHasTag(_unit, "ranged")`). Bomb Goblin's own definition already has `tags` including `"suicide"` (`UnitDefinitions.gml` line 445) but it's unused here. A second suicide-type unit later would need its own hardcoded branch instead of being picked up automatically.
