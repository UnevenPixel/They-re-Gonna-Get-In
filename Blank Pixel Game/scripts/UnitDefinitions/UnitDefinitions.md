# UnitDefinitions

`UnitDefinition` -- static, per-unit-TYPE data (name, cost, base stats, sprites, tags, orders, passives). Completely separate from `UnitDataBlock` (`UnitScripts.gml`), which is per-unit-INSTANCE runtime state that survives a station/redeploy swap (damage taken, status effects, which UnitDefinition to reapply).

Takes a single struct literal rather than positional args -- this constructor has too many fields for positional args to stay readable/safe against argument-order mistakes. A deliberate deviation from this codebase's usual positional-arg constructor convention (`Vector2`, `Order`, `ResourceCost`, `AnimationLibrary`, etc.) -- flag if you'd rather this matched those instead.

Registry is keyed by `object_index` (e.g. `oPeasantUnit`), NOT a string name like the Order registry uses -- ties directly into `instance_create_layer` for stationed-unit redeploy and removes any risk of a definition/object name mismatch. Flag if you'd rather this stayed string-keyed for consistency with `GetOrder`/`RegisterOrder`.

## Field reference

| Field | Type | Notes |
|---|---|---|
| `name`, `description` | String | Display name, flavor/tooltip text. |
| `cost` | Struct.Cost | Production cost (`Economy.gml`). |
| `maxHealth`, `attackDamage`, `attackRange`, `attackLeashRange`, `attackHitFrame`, `attackCooldownMax`, `attackAggroRadius`, `siegeSweepRadius`, `maxSpeed` | Real | Base combat/movement stats. |
| `sprites` | Struct.AnimationLibrary | idle/walk/attack + extras. |
| `icon` | Asset.GMSprite, optional | Small (8x8) UI icon shown inline before this unit's name in text, e.g. "Trains [icon]Peasant" (`BuildingHoverDescriptionText`). See `UnitIconTag` below, which turns this into a Scribble inline-sprite tag. |
| `smallSprite` | Asset.GMSprite, optional | ~16x20, bottom-center-anchored "small" full-body sprite, distinct from `sprites.idle` (sized for in-world rendering, not a UI window) -- used inside the Item/Unit Window on the building hover card (`BuildingHoverItemIcon`). |
| `palette` | Asset.GMSprite, optional | A 1px-wide, 2-frame "Pallete" sprite (matches this project's existing spelling of the asset name, e.g. `sPeasantPallete`) -- frame 0 lists the unit's original swappable colors (one texel per row), frame 1 the replacement, used by `shPaletteSwap` to recolor TEAM.ENEMY instances (`PaletteSwapScripts.gml`). Undefined for any unit without a Pallete sprite yet -- `PaletteSwapDrawUnit` skips shading entirely in that case, so the unit draws unshaded on both teams. |
| `availableOrders` | Array\<String\> | Order names this unit type can receive. |
| `tier` | Real, default 1 | Combat-XP tier (see `GainXP` in `ApplyDamage`, `UnitCombatHelpers.gml`) -- +1/+3/+5 XP per Tier 1/2/3 kill. Every unit is Tier 1 for the MVP; no real tier design exists yet beyond that. |
| `tags` | Array\<String\>, default [] | For search scripts -- see `UnitHasTag`. |
| `passives` | Array\<Struct\>, default [] | Still free-text-only ({name, description}), shown verbatim on hover cards. The "Stationed Effect" entry's real numeric magnitude (where one exists) lives SEPARATELY in `stationedBonuses` below -- nothing enforces the two stay in sync, keep them worded consistently by hand. "Deployed Effect" entries remain entirely inert (no hook exists). |
| `projectileObject` | Asset.GMObject, optional | The projectile a ranged unit fires (`SpawnProjectile`, `ProjectileScripts.gml`). Leave unset for melee units; a "ranged"-tagged unit with no `projectileObject` just logs and no-ops when it tries to fire. |
| `stationCost` | Real, default 0 | Gold cost to station/deploy, per the "Project Azurite Data Sheets" "Station Deploy Cost (GOLD)" column. Both display data (`UnitHoverStationFlavorText`) AND the real functional gate/spend for both directions -- `GetUnitStationCost` (`StationScripts.gml`) wraps it into a spendable `Cost`, spent via `Purchase()` by the "station" order and `DeployStationedUnit`. NOT copied onto live instances by `UnitApplyDefinition` -- every consumer already has the `UnitDefinition` in hand, so duplicating it there would be dead data to keep in sync. |
| `stationedBonuses` | Array\<Struct\>, default [] | The FUNCTIONAL counterpart to the "Stationed Effect" passives flavor text. Each entry is `{type, amount}` -- type is one of `allResourceProduction`/`goldProduction`/`unitHealth`/`unitDamage`/`trainingSpeed`, amount is a fractional bonus (0.05 = +5%). `GetStationedPassiveBonuses` (`StationScripts.gml`) sums `amount` onto `StationedBonuses[type + "Bonus"]` once per live `oUnitStationed` of this type on a team -- every entry stacks linearly per unit stationed, matching each unit's "(stacks per X stationed)" flavor wording. Archer's "Ranged attacks from the wall" passive is deliberately NOT represented here -- that would mean a garrisoned (non-live) unit actively firing on enemies, a real new combat mechanic rather than a stat multiplier; explicitly out of scope for now. Leave `[]` for any unit whose Stationed Effect has no numeric hook yet. |
| `gibSprite` | Asset.GMSprite, optional | This unit's own unique on-death gib sprite (single frame), spawned alongside the general chunks by `SpawnUnitDeathGibs` (`GibScripts.gml`). Undefined for any unit with no unique gib sprite yet. Mud Golem is excluded from the whole gibbing system regardless of this field. |
| `usesGeneralChunks` | Bool, default true | False skips the shared `sGeneralChunks` burst entirely for this unit's death (still gets the instant blood splatter, its own `gibSprite` if it has one, and the death blood-pixel burst). Only Bomb Goblin sets this false -- it already has its own explosion animation and no unique gib sprite, so generic debris chunks would look mismatched. |
| `productionBuildingDamageBonus` | Real, default 0 | The FUNCTIONAL counterpart to Knight's "Deployed Effect" flavor text ("Bonus damage against production buildings"), same flavor-text-to-numeric-field pattern as `stationedBonuses`. Fractional bonus (0.5 = +50%), applied ONLY when melee hits a building that's an `oResourceBuildingParent` (WaterPump/WheatField/Sawmill/GoldMine/IronMine -- see `UnitTryDealDamage`) -- NOT training buildings or the castle. Scoped specifically to "production buildings" per the flavor text's own wording; if a future unit needs a bonus against a different building category, this field's name/scope needs revisiting rather than reusing it as-is. |

## Key functions

`GetDamageTaken`/`SetDamageTaken` read/write `damageTaken` off any damageable instance -- a unit (stored at `unitData.damageTaken`, survives a station/redeploy swap) or a building (stored directly, `oBuildingParent` has no unitData/station concept). `GetCurrentHealth` derives `maxHealth - GetDamageTaken(_instance)` fresh every call -- deliberately not stored as its own field, so there's one source of truth. Named generically (not `UnitCurrentHealth`) since buildings use it too now -- renamed when building HP was added, only one caller (`ApplyDamage`) existed at rename time.

`UnitApplyDefinition(_unit)` looks up the unit's `UnitDefinition` and copies every static stat onto the instance, stamps `unitData.unitType`, and scales `maxHealth`/`attackDamage` by the unit's team's current `unitHealthBonus`/`unitDamageBonus` (Mud Golem/Soldier's stationed passives, `GetStationedPassiveBonuses`), rounded to the nearest whole number. The bonus is baked in ONCE, at whatever moment this function runs -- NOT re-applied retroactively to units already alive when a new booster gets stationed later, and not removed if that unit later redeploys out (see `GetStationedPassiveBonuses`'s own doc comment, `StationScripts.gml`, for why this deliberately skips full dynamic re-application).

IMPORTANT: `_unit.team` must already be its FINAL value before `UnitApplyDefinition` runs, or the bonus for the WRONG team gets baked in. It's called from `oUnitParent`'s Create event (still the TEAM.PLAYER default at that point for any spawn path that overrides team AFTER creation -- see the HAZARD comment in `oUnitParent/Create_0.gml`), so every such path must call it again after its team override. `DeployStationedUnit` and `TrainingSpawnUnit` both do.

`UnitIconTag(_unitDef)` translates a `UnitDefinition`'s icon sprite into the Scribble inline-sprite tag that renders it ("[spriteName,0]"), mirroring `ResourceIconTag`'s shape but resolved via `sprite_get_name` since each unit has its own distinct icon sprite asset rather than one shared frame-strip.

## Registered units -- data provenance notes

Attack timing/range/speed fields (attackRange, attackLeashRange, attackHitFrame, attackCooldownMax, attackAggroRadius, siegeSweepRadius, maxSpeed) are still placeholders, not balanced values -- the source data sheet doesn't specify any of these, only name/limit/HP/DMG/cost/upkeep/time/effects/source building. `maxHealth`, `attackDamage`, and `cost` ARE sheet-sourced and should be treated as real. Per-unit Upkeep (Stationed) from the sheet still has no home in either `UnitDefinition` or `BuildingDefinition` and is deliberately NOT added as a field -- no upkeep/drain system is designed yet.

**2026-08-30 follow-up:** every unit's `maxSpeed` was halved per explicit request ("reduce all unit movement speed by half") -- Peasant/Soldier/Archer 1 → 0.5, Bomb Goblin 2.2 → 1.1, Mud Golem 0.6 → 0.3, Knight 0.9 → 0.45. A flat halve of each existing (already-placeholder) value, not a re-derivation from any new target pacing -- relative ordering between units (Bomb Goblin fastest, Mud Golem slowest) is unchanged. `SteeringBehaviors.gml`'s steering math and `agent.maxSpeed` copy in `UnitApplyDefinition` needed no changes -- both already read this field live, nothing hardcodes the old values elsewhere.

- **Peasant**: `maxHealth`/`attackDamage`/`cost` were corrected at some point to match the data sheet / `PeasantWard.trainCost` (previously water20+wheat10+coins5-style values, now water 20 / 10 HP / 2 DMG).
- **Bomb Goblin**: sheet lists `attackDamage` as "20 AOE" -- self-destruct-on-hit is real (`UnitTryDealDamage` sets `pendingSelfDestruct`), but true AoE (hitting more than the single `_target`) is still not implemented. `palette` sprite asset is misspelled `sBombGolbinPallete` ("Golbin" not "Goblin") on disk/in the .yyp -- not a typo introduced here, that's the actual existing asset name; flag if you want it renamed (every other `sBombGoblin*` asset uses the correct spelling). `usesGeneralChunks: false` -- already has its own explosion animation and no unique gib sprite.
- **Mud Golem**: "Deployed Effect" (muddy ground slow-on-death) is flavor-text only, NOT implemented -- no on-death area-effect hook exists. Mud Golem is excluded from the entire gibbing system (both `SpawnUnitDeathGibs`/`SpawnUnitHitBlood` hard-exit for it specifically), not via `gibSprite`/`usesGeneralChunks` -- per explicit request ("except the golem, we will handle his").
- **Soldier**: `unitHealth`/`unitDamage` stationed bonuses stack in the same pool as Mud Golem's `unitHealth` bonus.
- **Archer**: `attackRange` (96) is a stand-in for "ranged" under the melee-derived attack state shape, a judgment call, not sheet-sourced. `stationedBonuses` deliberately omitted -- "Ranged attacks from the wall" would mean a garrisoned unit actively firing on enemies, a new combat mechanic rather than a stat multiplier, explicitly out of scope for now. Upkeep (1 Wheat / 3 sec per data sheet) is still not implemented.
- **Knight**: `productionBuildingDamageBonus: 0.5` implements the "+50% bonus damage against production buildings" flavor text (picked directly from "make it 50% more damage for now"). Its `stationedBonuses` trainingSpeed entry stacks linearly per Knight stationed like every other unit, even though the flavor text doesn't explicitly say "(stacks per Knight stationed)" the way others do -- applying the same rule for consistency rather than special-casing it to a flat one-time bonus; flagging the wording gap, not treating it as a deliberate no-stacking spec.

## API

- `UnitDefinition(_data)` constructor -- see field reference above.
- `RegisterUnitDefinition(_objectIndex, _definition)`, `GetUnitDefinition(_objectIndex)`.
- `UnitHasTag(_unit, _tag)`, `UnitIconTag(_unitDef)`.
- `GetDamageTaken(_instance)`, `SetDamageTaken(_instance, _value)`, `GetCurrentHealth(_instance)`.
- `UnitApplyDefinition(_unit)`.
- `RegisterAllUnitDefinitions()` -- registers Peasant/Bomb Goblin/Mud Golem/Soldier/Archer/Knight. Call once at game start (`oGameControl`'s Create event).
